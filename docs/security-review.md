# Security review (Milestone 5)

Scope: the web app, APIs, worker, ingestion pipeline, database, Redis, and the Compose
deployment recipe, at the commit tagged in `docs/release-report.md`. This was a self-review of
code and configuration, with targeted tests. It is **not** an independent penetration test,
which is listed as a next action.

## 1. Assets and trust boundaries

| Asset                                                            | Why it matters                                                                   |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Source registry, outlet labels and their provenance              | The product's credibility; wrong labels mislead readers                          |
| Admin capability (bearer token or admin session)                 | Can change labels, activate feeds, remove stories                                |
| Session secret, admin and metrics tokens, DB and Redis passwords | Full compromise if leaked                                                        |
| Readers' privacy                                                 | No tracking is a product promise; IPs and behaviour must not be stored           |
| Server-side fetching                                             | The worker fetches URLs, so a malicious URL could reach internal services (SSRF) |

Untrusted inputs: every HTTP request (query strings, bodies, headers including
`X-Forwarded-For`), **every byte of every publisher feed**, robots.txt files, redirects and DNS
answers during fetches, and admin-entered URLs and text.

## 2. Threats and controls

| Threat                                  | Control                                                                                                                                                                                                                                                                                                 | Evidence                                                                                                                              |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| XSS via feed content                    | Feeds are parsed as data. Titles and excerpts are reduced to plain text (tags, entities and control characters handled) and rendered by React as text, never as HTML. No feed images are stored or shown                                                                                                | `lib/ingest/text.ts`; `tests/unit/text.test.ts`, `feed-parser.test.ts`                                                                |
| XSS via URLs (`javascript:`, `data:`)   | **Fixed in M5.** Admin-entered `termsUrl` and `sourceUrl` must be http(s) with a DNS hostname (`z.url({ protocol, hostname })`). Every rendered external link goes through `safeHref()`, which returns null for anything but http(s). Feed article URLs are canonicalised http(s) at ingestion          | `lib/admin/service.ts`, `lib/security/safe-url.ts`; `tests/unit/security-hardening.test.ts`                                           |
| Script injection generally              | CSP with a per-request nonce and `'strict-dynamic'` (no `unsafe-eval` in production), `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`                                                                                                                            | `lib/security/headers.ts`, `proxy.ts`; `tests/unit/security-headers.test.ts`; smoke test checks the header                            |
| Malicious map asset                     | **Hardened in M5.** `/geo/*` is served with its own CSP (`default-src 'none'`, embeddable only by our pages) and `nosniff`                                                                                                                                                                              | `next.config.ts`; `tests/unit/security-hardening.test.ts`                                                                             |
| Clickjacking                            | `frame-ancestors 'none'` + `X-Frame-Options: DENY` on pages                                                                                                                                                                                                                                             | headers test                                                                                                                          |
| SQL injection                           | Prisma queries, and `Prisma.sql` tagged templates for raw SQL: every value is a bound parameter; identifiers come from fixed code paths only. Sort keys are allow-listed; cursors are signed, versioned and bound to the sort                                                                           | `lib/search/articles.ts`; integration test "treats SQL-like input purely as data"                                                     |
| SSRF from feed, robots or redirect URLs | Public-address policy (ipaddr.js) on **every** resolved address, with the DNS answer pinned for the connection (no rebinding); http(s) and ports 80/443 only; each redirect re-validated (default max 3, `INGEST_MAX_REDIRECTS`); size, time and decompression caps; URL checked _before_ robots lookup | `lib/ingest/safe-fetch.ts`, `ip-policy.ts`; `tests/unit/ip-policy.test.ts`, integration ingestion tests (private IP → `SSRF_BLOCKED`) |
| XML attacks (XXE, billion laughs)       | DOCTYPE/ENTITY declarations rejected before parsing; XML validated; size-capped input                                                                                                                                                                                                                   | `lib/ingest/feed-parser.ts`; doctype fixture test                                                                                     |
| ReDoS from hostile robots.txt           | **Fixed in M5.** Robots patterns are capped at 512 characters and 8 wildcards; longer patterns are ignored (fail-closed for that rule), so matching stays linear                                                                                                                                        | `lib/ingest/robots.ts`; `tests/unit/security-hardening.test.ts`                                                                       |
| Abuse and scraping of APIs              | Redis fixed-window rate limits per route class, keyed by a salted, daily-rotating hash of the client address (no raw IPs stored). Page size max 50; counts capped at 1000; query length max 200                                                                                                         | `lib/api/rate-limit.ts`, `contracts.ts`                                                                                               |
| CSRF on admin and preference writes     | `SameSite=Lax` HttpOnly session cookie (`__Host-` prefix on https), plus a same-origin check on every state-changing admin request and server action                                                                                                                                                    | `lib/auth/session.ts`, `lib/auth/admin.ts`; admin API tests                                                                           |
| Session forgery and fixation            | HMAC-SHA256 signed cookie with expiry; constant-time comparison; OIDC with PKCE, state and nonce in a signed transient cookie                                                                                                                                                                           | `lib/auth/*`; `auth-preferences` integration tests (incl. a mock OIDC provider)                                                       |
| Privilege escalation                    | Admin = bearer token (≥ 32 chars) **or** a session user listed in `ADMIN_USER_IDS`; checked server-side on every admin route and action; dev login refused off localhost; every admin write audited                                                                                                     | `lib/auth/admin.ts`, `AdminAuditLog`; permission tests                                                                                |
| Secrets exposure                        | Secrets only in environment variables, validated at boot (weak, placeholder or "insecure" values rejected off localhost). Client bundles scanned for secrets: none found. `.env*` git-ignored except the example                                                                                        | `lib/env.ts`; `tests/unit/env.test.ts`; bundle scan in M4                                                                             |
| Over-privileged database access         | Production recipe: the app connects as `frealgo_app` (DML only, no DDL); only the one-shot `migrate` job uses the owner role                                                                                                                                                                            | `deploy/docker-compose.prod.yml`, `docker/postgres/init-roles.sh`                                                                     |
| Exposed infrastructure                  | Production: only Caddy publishes ports (80/443). Postgres and Redis are on an internal network; Redis requires a password; worker health and metrics are internal; the web `/api/v1/metrics` needs a bearer token and Caddy blocks it publicly                                                          | `deploy/`                                                                                                                             |
| Information leakage                     | No `X-Powered-By`; generic error bodies with a request id; structured logs exclude IPs, cookies and bodies                                                                                                                                                                                              | `lib/api/handler.ts`, `lib/log.ts`                                                                                                    |
| Reader tracking                         | No cookies for anonymous readers (preferences stay in the browser); no third-party scripts, fonts or images; client telemetry is opt-out-able anonymous counters only (no ids, no IPs, no URLs)                                                                                                         | `docs/privacy-accessibility-audit.md`                                                                                                 |
| Unlicensed content redistribution       | Headline + short excerpt + link only; no full text, no images; feeds inactive until an operator records a terms review                                                                                                                                                                                  | `docs/data/source-methodology.md`; `runSource` gate test                                                                              |
| Supply chain                            | Exact-pinned dependencies (`save-exact`) with a lockfile; `npm ci` in CI and Docker; `npm audit` in CI; licence audit                                                                                                                                                                                   | `.npmrc`, `.github/workflows/ci.yml`, `docs/licenses.md`                                                                              |

## 3. Findings from this review

| #   | Severity              | Finding                                                                                                                                                                                                                               | Status                                                                                            |
| --- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1   | High                  | Admin-entered `termsUrl`/`sourceUrl` accepted `javascript:` and `data:` URLs (`z.url()` default), so stored XSS was possible for any viewer of a source page or label                                                                 | **Fixed**: http(s)-only validation plus `safeHref()` on every rendered external link; tests added |
| 2   | Medium                | robots.txt patterns with many `*` wildcards could cause super-linear regex matching in the worker (publisher-controlled input)                                                                                                        | **Fixed**: pattern length and wildcard caps; tests added                                          |
| 3   | Low                   | `/geo/world-map.v*.svg` was served without its own CSP; an SVG opened directly is a document that could run script if the file were ever tampered with                                                                                | **Fixed**: restrictive CSP and `nosniff` on `/geo/*`                                              |
| 4   | Medium (availability) | Postgres in Docker failed under concurrent load (`/dev/shm` 64 MB; SQLSTATE 53100), and cold-cache requests stampeded the DB                                                                                                          | **Fixed**: `shm_size: 256mb`; single-flight cache loads (see `docs/performance.md`)               |
| 5   | Info                  | `npm audit` (including dev dependencies) reports GHSA-vfj7-8cjw-p6xm in `braces@3.0.3`, reached only through `eslint-config-next` → `fast-glob` → `micromatch`. It is lint tooling that never runs on untrusted input and never ships | **Accepted** (dev-only). `npm audit --omit=dev`: 0 vulnerabilities                                |

## 4. Accepted risks

- **`style-src 'unsafe-inline'`**: required by Next.js and Motion inline styles (ADR-009). Script
  execution remains nonce-gated, so the residual risk is limited to CSS-based exfiltration on
  pages that render no secrets.
- **Rate limiting depends on the proxy** setting `X-Forwarded-For`. Exposed directly, clients
  could rotate the header. The production recipe only publishes Caddy, which overwrites it.
- **In-process caches and API metrics are per instance.** That is acceptable at this scale;
  documented in operations.
- **Admin bearer token** is a shared secret. For more than one operator, prefer OIDC sessions
  with `ADMIN_USER_IDS` and rotate the token.
